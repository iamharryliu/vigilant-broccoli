# RabbitMQ

RabbitMQ is an open-source **_message broker_** that enables applications, services, and systems to communicate with each other asynchronously.

- Producer – The component that sends messages.
- Queue – The buffer where messages are stored.
- Consumer – The component that processes messages from the queue.

## Getting Started (local)

```
npm i amqplib
fly proxy -a APP_NAME 5672
```

- Run a local docker container `docker run -d --name rabbitmq -p 5672:5672 -p 15672:15672 rabbitmq:management`
- Visit `http://localhost:15672/` and use `guest` for username and password.

## Deployment

Production runs on the OCI `rabbitmq-vm` (`infrastructure/terraform/oci.tf`, `cloud-init-rabbitmq.yaml`) as `rabbitmq:3-management-alpine` in Docker Compose. The admin user and password are generated by Terraform (not `guest`) and stored in Vault as `RABBITMQ_CONNECTION_STRING`.

- **AMQP** — TLS only on `5671`, open to `0.0.0.0/0` for the fly.io consumers (`listeners.tcp = none`). The leaf cert is signed by a Terraform-generated private CA and carries the `rabbitmq` and `localhost` SANs.
- **Management UI** — `https://queue.harryliu.dev`, behind Cloudflare Access (owner email). Port `15671` is not published on the host and not open in the security list; a `cloudflared` container in the same Compose stack reaches `https://rabbitmq:15671`, verifying the cert against the private CA.
- Rotate the password with `infrastructure/terraform/packer/scripts/rotate-rabbitmq-password.sh`.

The `guest`/`guest` local container above is for local development only.
