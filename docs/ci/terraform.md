# Terraform

Where infrastructure-as-code lives, how it is applied, and how drift is detected.

- Infrastructure-as-code lives in `infrastructure/terraform/`, driven by the `pnpm tf:*` scripts — resource inventory and operations in [repo-operations.md](../repo-operations.md). Never change Terraform-managed configuration in a provider dashboard or the GitHub UI — the next apply reverts it.
- `pnpm tf:*` exports provider credentials through `load-vault-tf-env.sh`, which reads live Vault `kv/data/secrets` (5s timeout) and falls back to the latest Bitwarden backup with a stderr notice when Vault is unreachable. The fallback is only as fresh as the last `backup-secrets.sh` run.
- Vault's JWT roles and `github-actions-*` policies are a separate root module, `infrastructure/terraform/vault/` (HCP workspace `vigilant-broccoli-vault`, local execution), because the main workspace creates the VM Vault runs on and reads its own credentials from Vault. `pnpm tf:vault:plan`/`tf:vault:apply` reach Vault at `vault.vigilant-broccoli.app` with the root token and Cloudflare Access service token from GCP Secret Manager (`vault/scripts/load-vault-provider-env.sh`, no Bitwarden fallback), and `pnpm tf:apply` runs `tf:vault:apply` last, after post-apply has bootstrapped Vault. Removing a role or policy there destroys it on apply. `run-vault-post-init.sh` still writes the same roles and policies and keeps Vault's bootstrap (init, mounts, `auth/jwt/config`); keep both in sync until its writes are removed. `cron-terraform-drift` does not plan this workspace yet.
- `cron-terraform-drift` runs `terraform plan -detailed-exitcode -lock=false` daily and fails when config, state, and the real infrastructure disagree — a dashboard edit, a merged-but-unapplied change, or a resource deleted out of band. Applies stay local (`pnpm tf:apply`); the workflow only reads. It authenticates to GCP as the read-only `github-actions-tf-drift` SA (`github-actions-tf-drift.tf`), whose WIF provider accepts only this workflow on `main`. The repo is public, so the plan body is never printed — the job summary lists changed addresses and actions only. When it goes red, run `pnpm tf:plan` locally for the full diff. A new Google resource type the SA can't read (a 403 during refresh) needs a read role added there, not a wider shared SA.
