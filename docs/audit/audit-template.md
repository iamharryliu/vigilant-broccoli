# Audit Notes

Point-in-time reviews of the codebase for a class of issues. Generated by `pnpm agentic:audit "<scope>"` (see [DEV_TOOLING.md](../DEV_TOOLING.md)) or written by hand.

Every note follows the same template — keep it **brief**: a findings table over prose, every finding tied to a concrete path.

## Template

```markdown
# Audit: <Title>

> <one-line restatement of what was audited> · <YYYY-MM-DD>

## Scope

1–2 sentences: what was reviewed (paths, patterns searched) and what was looked for.

## Findings

| #   | Severity | Location              | Finding | Remediation |
| --- | -------- | --------------------- | ------- | ----------- |
| 1   | High     | `path/to/file.ext:12` | …       | …           |
| 2   | Medium   | `path/to/file.ext:34` | …       | …           |

Severity is one of Critical / High / Medium / Low / Info. If nothing was found, write a single row stating "No findings" and say what was checked.

## Recommendations

Prioritized next steps: what to fix first, and any systemic follow-up (e.g. a lint/CI rule to prevent recurrence).
```

## Rules

- Every finding cites a concrete path (`path/to/file.ext:12`) and a severity.
- Report only real issues found in this repo — do not speculate. An empty audit (no findings) is a valid, useful result.
- Keep it scannable. Group or summarize when findings are numerous.
