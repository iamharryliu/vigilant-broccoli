# R&D Notes

Concise research notes weighing options for a decision. Generated by `pnpm agentic:rnd "<question>"` (see [DEV_TOOLING.md](../DEV_TOOLING.md)) or written by hand.

Every note follows the same template — keep it **brief**: tables and short sentences over prose, no filler.

## Template

```markdown
# R&D: <Title>

> <one-line restatement of the question> · <YYYY-MM-DD>

## Context

2–3 sentences: what is being decided and why. Cite repo paths (`path/to/file.ext:12`) when the question touches existing code.

## Alternatives

| Option       | Pros | Cons | Cost | Security | Scalability |
| ------------ | ---- | ---- | ---- | -------- | ----------- |
| **A — name** | …    | …    | …    | …        | …           |
| **B — name** | …    | …    | …    | …        | …           |
| **C — name** | …    | …    | …    | …        | …           |

## Recommendation

The chosen option and why, in 2–4 sentences. Name the runner-up and the condition under which it would win instead.

## Sample Implementation

Smallest concrete starting point for the recommendation — a short code block or numbered steps citing the repo files/patterns to follow. Not a full build-out.
```

## Rules

- Always include **Alternatives** (≥ 2), a **Recommendation**, and a **Sample Implementation** — in that order.
- Fill every column of the Alternatives table; use `—` when a cell genuinely does not apply.
- Keep it scannable. If a section runs long, cut it.
