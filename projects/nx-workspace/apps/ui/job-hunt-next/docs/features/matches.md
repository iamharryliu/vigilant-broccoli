# Matches

- Matches scores LinkedIn search results against the skills in the career experience file, opened from the sidebar.
- A second bookmarklet, behind the Matches page's help icon, scrolls a LinkedIn job search page, opens each result and posts each description to the app as soon as it is captured, so results appear while the scan runs and the page shows a progress banner (cleared on completion with a toast, or after 60 seconds without an update if the LinkedIn tab is closed). The app saves the batch to the `job_matches` table of the local SQLite database, keyed by posting URL, and shows the page. Each capture adds to the stack: postings already stored are refreshed, others stay until removed one by one or with Clear all.
- Each posting is scored on the share of the skills it names (from a fixed vocabulary in `job-matches.utils.ts`) that the Skills table covers (a row covers every vocabulary skill its text names, so `TypeScript / JavaScript` covers both): strong from 70%, okay from 45%, otherwise weak, and unknown when no vocabulary skill appears. Skills listed are tags; skills missing are gap tags, and the most common gaps are summarised above the list.
- Scoring runs in the browser on every load, so editing the Skills table re-scores stored postings without a new capture.
- The demo build is read-only and starts empty.
- Suggest skills starts a Claude run (kind `skill-suggestions`, visible on Runs, allowed only `Read` and `Write`) over the stored postings and the current vocabulary. It writes skills the postings name that the vocabulary lacks, with aliases and a posting count; the app drops empty, oversized and already-known names before storing them in the `job_match_skills` table as suggestions. Suggestions appear on Matches; accepting one adds it to the vocabulary for every posting (it then counts as a match or a gap), dismissing one stops it being suggested again, and an added skill can be removed. The run runs beside applications, since it reads no career file. The demo build disables it.
- Skills outside the vocabulary count only when a Skills row names them verbatim, so a new technology never shows as a gap until it is added to the vocabulary.
- Cards show an Easy Apply badge when LinkedIn offered it, read from the card's label or the detail pane's button. The filter row narrows the list by match level and by Easy Apply only; filters reset on reload. Postings captured before Easy Apply was recorded show no badge and are excluded by that filter until captured again.
- Clear all asks for confirmation, then removes every stored posting and every suggested skill; skills the user added stay, and dismissed ones stay so they are not suggested again.
- Postings sort by best match (default), fewest gaps, most skills matched, newest captured, or recently posted; the choice is remembered in the browser. Recently posted uses LinkedIn's relative age ("2 days ago") read above the description at capture, subtracted from the capture time, so the date is approximate and postings without an age sort last.
