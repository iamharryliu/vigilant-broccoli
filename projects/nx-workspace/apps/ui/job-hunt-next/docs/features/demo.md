# Public demo

Job Hunt's public Vercel demo lets visitors browse Jordan Rivera's fictional career profile, four sample applications (postings, identified gaps and cover letters, with resume and cover-letter PDFs for the first), and illustrative run history including a failed run and import runs.

## Deployment

`nx run job-hunt-next:deploy:demo` creates or updates `demo-job-hunt-next` through the shared Vercel deploy script. The existing affected demo workflow discovers this target; manual deployment selects `job-hunt-next` and environment `demo`. The URL is `https://demo-job-hunt-next.vercel.app/` and is registered in Upptime, pages-index and browser quick links. The build copies public demo PDFs beside the configured `.next` output so Vercel includes them as static assets.

The demo has no Anthropic credentials, database or writable storage. `NEXT_PUBLIC_JOB_HUNT_DEMO=true` is fixed into the build for both browser controls and the server proxy, and is part of the Nx build cache inputs. Every API path is answered by the proxy from bundled sample data or rejected; unknown routes never reach live handlers. All writes, career imports, resets, deletion and Claude execution are rejected with HTTP 403. The demo shows a notice and disables save/reset/run controls, while career preview, PDF viewing, copying and run history remain available. Data and run output are illustrative, not generated by a live Claude call.

The standalone deployment always performs a fresh build and checks its server, standalone, static, skill and template output plus public documents for the owner's contact details before upload. The repository root package manifest is excluded from file tracing because its maintenance scripts contain owner-specific addresses. Public PDFs contain the fictional sample profile. They are static snapshots; regenerate them with the app's bundled PDF scripts after changing sample content.

For local preview, run `NEXT_PUBLIC_JOB_HUNT_DEMO=true nx serve job-hunt-next`. Rebuild without that variable for the normal app. Staging and production targets continue publishing the self-hostable Docker image; full operation still requires persistent career/application files, SQLite and a Claude Code process. Fly is a suitable container host for that full workflow; Vercel is sufficient for the read-only demo.

## Free Tier

The demo adds one Vercel Hobby project and uses bundled data without an external paid API or persistent volume. Hobby is limited to personal, non-commercial use; current allowances include 100 GB monthly fast data transfer, 1 million invocations, 4 active CPU hours and 360 GB-hours of provisioned memory. Usage shares the team's allowance; it is not a separate allocation for this demo. See [Vercel Hobby limits](https://vercel.com/docs/plans/hobby).
