# Bookmarks

The Bookmarks page wraps `QuickLinksPanel` with search autofocus and browser-local favorite toggles. Badge views prefix favorites with a star (toggle them in rows view), and favorites appear once in their own group at the top. Favorites use the shared `quick-links-favorites` key on this origin, separately from the bookmark list; identical links share a favorite state. There is no separate edit mode: through `QuickLinksPanel`'s `getMenuActions` prop, each row in the rows view has an ellipsis menu (copy button, then ⋯) with Edit and Delete, and no external-link button because clicking the row already opens the link. Delete asks for confirmation through the menu's built-in `DeleteItemConfirmationDialog`. ArrowUp and ArrowDown move between the rows and the search field in every view. The Add sidebar item (always visible) and the Edit menu item open a full-height-on-mobile `Dialog` form; saving or cancelling closes it. The subsection field is a select of existing subsections plus "No subsection" and "New subsection…", which reveals a text input. Export, Import and Clear all bookmarks are buttons under Settings > Bookmark data; Import opens the import dialog, whose "Set to default JSON" button fetches `default-bookmarks.json` into the textarea (Merge or Replace then applies it).

Dropping a link anywhere on the page (from the address bar, a page or another app) opens the Add dialog prefilled with the URL and the hostname as the label. `dropped-link.ts` reads `text/uri-list` or `text/plain` and ignores non-HTTP(S) payloads; drops onto inputs and file drags are left alone, and a dashed overlay shows while a link is dragged over the window.

A Help sidebar item below Settings opens a centered `Dialog` listing, with space between points, behaviors the UI does not make explicit (drag-and-drop, arrow-key navigation, favorites, local-only storage, import modes); add new hidden behaviors there via the `HELP_*` keys in `en.json`.

Navigation is the shared `Sidebar` from `react-lib-higher-level`, as in hearth: a fixed icon rail that expands on hover (content padding follows through `peer-hover`) and becomes a drawer below `md`, opened by a menu button in the page header. Its items are Bookmarks, Add bookmark, Settings and Help (Add bookmark and Help are buttons, not pages), each with an icon, and the selected page is the URL: `/` for Bookmarks and `/settings` for Settings (under the Vite base path), updated with `history.pushState` so Back and direct links work; Cloudflare Pages serves `index.html` for the unknown `/settings` path. Settings holds a full-width segmented control for the theme (System, Light or Dark) backed by `useTheme`; System follows the OS and clears the saved override, and the choice lives under the app's own `bookmarks-react-theme` key.

`use-bookmarks.ts` stores `{ bookmarks: QuickLink[] }` under `bookmarks:v1`. Reads and writes are guarded: corrupt data falls back to an empty list, while failed writes keep the current session usable and show an export reminder. Data stays on this browser origin; there is no backend, auth or cross-device sync. Clearing browser data removes it, and staging, previews and production each have separate storage.

On first visit (no `bookmarks:v1` key) the app fetches `default-bookmarks.json` from the site root (under the Vite base path) and shows an empty list if it is missing or invalid; the seeded list is not persisted until the visitor changes it. The `generate-default-bookmarks` target (a dependency of `build` and `serve`) writes that file into the gitignored `public/` folder from `scripts/default-bookmarks.ts`, a label allowlist over `PUBLIC_QUICK_LINKS` in `@vigilant-broccoli/public-links` (browser links only, embed flags dropped; never private link libs). The allowlist excludes project/account-scoped consoles, staging hosts, private apps and any link to a `harryliu.dev` host, the vigilant-broccoli repo or its section (Cloud 8 Skate and the Vercel demos); `PUBLIC_QUICK_LINKS` itself is shared with pastebin, so it is curated here. Clear all bookmarks asks for confirmation in a `DeleteItemConfirmationDialog` and stores an empty list, which is not re-seeded. Self-hosters replace the served file to ship their own list; see [self-hosting.md](./self-hosting.md).

Only non-empty labels and HTTP(S) targets with `type: OPEN_TYPE.BROWSER` are accepted. The same validator handles forms, stored data and imports; shell types, args and embed options are rejected. Optional subgroup text is trimmed.

Export downloads `bookmarks.json`, an array of QuickLink objects. Import opens a `Dialog` with a `Textarea` whose placeholder is the expected JSON shape. Pasting, uploading through the file `Input` (`type="file"`) or dropping a JSON file on the dialog sets the textarea text, replacing what was there; it validates the entire text before enabling Merge or Replace, and shows invalid-JSON errors inside the dialog. Merge keeps existing entries and skips exact label/target/subgroup duplicates; Replace replaces the entire list, including with an empty array. Cancel leaves bookmarks unchanged.

## Free Tier

Cloudflare Pages uses three projects (staging, production and preview) within the shared 100-project allowance. Builds run in Actions and upload through Wrangler; Pages allows 20,000 files per site and 25 MiB per asset. No database or server runtime is provisioned.

Apply staging Access protection before the first staging deployment. Create/deploy the production Pages project before applying its custom-domain attachment and DNS record. No deployment or Terraform apply is part of local validation.
