# Preview Deployments

- `/preview-deployments` page (sidebar entry, `SIDEBAR_ROUTE.PREVIEW_DEPLOYMENTS`) lists every open PR with a deployed Cloudflare Pages preview, newest PR first. Each card links the PR (number and title) and shows its author and head branch, then each app with its alias (`pr-<n>.preview-<app>.pages.dev`, follows the PR), immutable build URL and short commit.
- The UI is `PreviewDeployments` from `@vigilant-broccoli/react-lib-higher-level` with the default `GRID` layout, shared with `vb-manager-next-mobile`; the page passes a `loadPreviewDeployments` loader that calls `/api/preview-deployments` through the app's `authFetch`. The component takes a loader rather than a fetch so `pages-index` can reuse it with a direct, tokenless GitHub call (`showServerTokenHint={false}` drops the server-token hint from the rate-limit message; see [deployments-page.md](../../../pages-index/docs/features/deployments-page.md)).
- Source of truth is GitHub Deployments, written by `deploy-preview.yml` with environment `pr-<n>/<app>` and a `payload` carrying the URLs; see [workflow-conventions.md](../../../../../../../docs/ci/workflow-conventions.md#pr-previews). No Worker, KV or app-side storage.
- `GET /api/preview-deployments` (`src/app/api/preview-deployments/route.ts`) calls `getPreviewDeployments` from `@vigilant-broccoli/github-workspace-js`, shared with `vb-manager-next-mobile`: two GitHub calls (`/deployments?per_page=100`, `/pulls?state=open&per_page=100`), keeping the newest deployment per environment for open PRs only. Successful results are cached in-process for 3 minutes, so Refresh within that window returns the same data (the page shows when it was fetched).
- The page fetches on load and on Refresh only, never polls: unauthenticated GitHub calls are limited to 60 per hour per IP. A rate-limited fetch shows an error with the reset time instead of an empty list.
- Optional `GITHUB_TOKEN` (read-only, public-repo access is enough) lifts the limit; it is commented out in `.env.local.example` so `fetch-secrets` never injects one. A token set in `.env.local` is also inherited by the dev dashboard's `gh` calls, which is why `serve`/`pm2` scrub the ambient variable; leave it unset unless the limit bites.
- Only the newest 100 deployments are read, so a long-lived PR's preview can drop off when many later deploys happen.
