# Settings

The `/settings` page, opened from the settings icon in the home header (shown when signed in or in local mode). Signed-out visitors see a sign-in prompt instead.

- **Tabs:** Tasks (list management), Import / Export and Account. Storage modes: see [database-storage.md](./database-storage.md). The board view is in [board-view.md](./board-view.md).
- **Task lists:** the add-list form sits in the row under the card title and the title's ellipsis menu has Delete all task lists (after confirmation; it keeps Google's undeletable default list, and in local mode an empty default list is recreated). Each row shows its active-task count and its ellipsis menu has Rename (inline; Enter saves, Escape cancels), Set as default list and Delete (after confirmation), through `/api/tasks/lists` `POST`/`PATCH`/`DELETE`. Google returns its own default list first and refuses to delete it, so that row's Delete is disabled when signed in to Google. Local and Database modes can delete any list while another remains.
- **Default list:** Google's API cannot reorder lists or change its default, so "Set as default list" is an app preference in `libs/default-task-list.ts` (`tasks-default-list-id`, with `-local` and `-database` suffixes in those modes). The home page copies it into the component's remembered-list key on mount, so each page load and mode switch opens on it. The Default badge marks it, falling back to the first list when none is set or the stored list was deleted. `useTaskLists` in `src/app/hooks/use-task-lists.ts` holds one list state for this card and the export card, updating it only after the API confirms.
- **Export task lists:** one checkbox per task list, with Select all and Clear all. Export fetches each selected list's tasks through `/api/tasks?taskListId=<id>` (no status filter, so completed tasks are included) and downloads `tasks-export-<YYYY-MM-DD>.json` shaped `{ exportedAt, taskLists: [{ id, title, tasks }] }`. The file also carries `kanban: { boards: [{ name, lanes: [{ taskListTitle }] }], sortModes }`, keyed by list title because list ids differ between stores and change on import; only lanes of exported lists are kept.
- **Import task lists:** Choose file reads a JSON file in the export shape. Lists are matched by title (ids are ignored because Google assigns new ones) and created when missing. Database and Local modes send each list in one `POST /api/tasks/import` (a single insert or store write); Google has no bulk call, so each task is one `POST /api/tasks` carrying its notes, due date and status, sent in reverse because Google inserts at the top. Imported tasks keep the file's order, a running "Imported N of M tasks" count shows while it runs, and importing the same file twice duplicates its tasks. A file with `kanban` also appends its boards to the active store's boards (new ids, lanes mapped back to lists by title; lanes whose list is missing are dropped) once the lists exist, so importing twice duplicates boards too.
- **Active store:** the home header's Google / Database / Local select with icons (beside the settings icon) switches and shows the store; the Settings header carries the same select (`StorageModeSelect`).
- **Account:** Sign out, then return to the home page. `/embed` has no settings link and keeps its own sign-in flow.

In local mode both list cards act on the browser's local lists.

## Local mode

Two entry points switch to local mode through `libs/local-mode.ts` (the mode itself lives in `libs/storage-mode.ts`): "Continue without signing in" on the signed-out tasks card (`onUseLocally` on `GoogleTasksComponent`), and the Local option of the select beside the settings icon. While it is set, the home page passes `localTasksAuth`, built with `createLocalTasksAdapter` from `react-lib-tasks`, whose `authFetch` answers the same `/api/tasks*` calls from the `tasks-local-store` localStorage key, so nothing reaches the server or Google. Voice and image parsing are not served locally.

Local mode never signs the user out: the Supabase session stays, so a signed-in user leaves through the select or Settings' Leave local mode without signing in again. Signed-out users get Sign in with Google, which clears the flag before redirecting. Local tasks stay in the browser and are not copied to Google; choosing local mode again shows them. Both modes share the component's remembered list (`STORAGE_KEY_SELECTED_TASK_LIST`), so every mode switch clears it: Google rejects a local list id and `/api/tasks` returns "Failed to fetch tasks".
