# Keyboard toolbar

- `AppShell` (`src/app/components/app-shell.tsx`) renders react-lib's `KeyboardAccessoryToolbar` on phones only (`isPhoneUserAgent` from common-browser, resolved after mount; tablets, iPad and desktop never see it).
- The toolbar shows while a text input, textarea or contenteditable has focus. It is anchored with `top: visualViewport.offsetTop + visualViewport.height` and `translateY(-100%)`, not a `bottom` offset from `innerHeight`, which iOS reports inconsistently while the keyboard is open or animating; it resyncs on viewport resize/scroll, window scroll and `focusin`. The bottom safe-area padding is dropped while the keyboard is open. Its `pointerdown` is prevented so tapping keeps focus and the keyboard open.
- Undo and Redo (`pressUndo`/`pressRedo`) dispatch a ⌘Z / ⌘⇧Z `keydown` so editors with their own history (the Notepad `SyncedTextEditor` via `onUndo`/`onRedo`) handle it; if no handler prevents it, they fall back to `execCommand('undo'|'redo')` on the browser's native stack.
- Enter (`pressEnter` in react-lib's `keyboard-accessory.utils.ts`) submits instead of inserting a newline, in every field type. It dispatches an Enter `keydown` on the focused field and, unless a handler prevented it (fields such as the Google Tasks textarea submit themselves on Enter), calls `requestSubmit` on the enclosing form. Fields with neither do nothing; the on-screen keyboard's return key still inserts newlines.
- Modelled on the web terminal toolbar in `infrastructure/code-server/web-terminal/public`.
