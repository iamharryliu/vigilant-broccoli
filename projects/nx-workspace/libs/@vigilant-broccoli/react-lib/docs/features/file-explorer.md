# File Explorer

- File browser, read-only unless upload/delete handlers are passed, over any backend that lists folders and serves file bytes: up button and breadcrumbs, name search, list/grid toggle, refresh, sortable Name/Size/Modified columns (folders first) and a status bar. Double-click opens a folder or opens a file in a new tab.
- Selection, the same in list and grid view: a click selects only that item and sets the anchor; Shift+click selects the range from the anchor in on-screen (sorted, filtered) order; Cmd/Ctrl+click toggles one item and moves the anchor. A cursor follows the last clicked or arrowed-to item. With the items area focused (a click focuses it), an arrow key moves the cursor and selects only that item, or the first item when nothing is selected; Shift+arrow selects the range from the anchor to the cursor. List view uses ArrowUp/ArrowDown; grid view uses ArrowLeft/ArrowRight for one item and ArrowUp/ArrowDown for one row, the column count read from the laid-out grid. Movement stops at the first and last item and scrolls the item into view. Enter opens the item when exactly one is selected. Keys are ignored with Cmd/Ctrl/Alt held, from focused controls inside the area, and while the context menu or delete dialog is open. Clicking empty space, navigating or back/forward clears it. Only visible items count, so a search never acts on hidden selections. The status bar shows the item's name and size for one selection and `N selected` for more.
- Context menu: right-clicking an item outside the selection selects only it; inside a multi-selection the selection is kept. One item offers Open (same as double-click) and, for a file with `onDelete`, Delete; several offer `Delete N files`, counting only files. A menu with no items does not open. Empty space and the toolbar keep the browser's native menu. Built on [`ContextMenu`](./context-menu.md), one root per item.
- Preview sidebar: shown while exactly one file is selected and collapsible from its edge tab. Images (`png`, `jpg`, `jpeg`, `gif`, `webp`, `svg`) render as an `<img>`, PDFs in an `<iframe>`, other files as a large icon plus their extension; below come the name, size, modified date and an Open button (same as double-click). Selecting a folder or several items, clearing the selection, navigating or deleting the file removes it.
- Grid thumbnails: in grid view image files show a thumbnail instead of the icon, fetched only once the tile scrolls into view (`IntersectionObserver`); the icon stays while loading or on failure. List view keeps icons.

## Usage

- Point `listEndpoint` at a route returning `{ entries: FileEntry[] }` for `?path=<relative>` and `fileEndpoint` at one returning the file's bytes. `FileEntry` and `FILE_ENTRY_KIND` come from `@vigilant-broccoli/common-js` so the route and the component share one contract.
- `fetcher` (default `fetch`) lets the caller supply an authenticated fetch. A plain link or `src` cannot carry a bearer token, so opened files, previews and thumbnails all fetch the blob from `fileEndpoint` and use an object URL. Previews and thumbnails revoke theirs when the selection changes or they unmount and drop responses for a selection that is no longer current; the preview shows a skeleton while loading and inline error text on failure. `onError` receives open-file failures, `defaultSort` sets the initial order (default Name ascending) and `toolbarAction` adds a node to the toolbar.
- Optional `onUpload(folderPath, files)` adds an upload button that picks files for the open folder (`''` at the root); optional `onDelete(entry)` adds a delete button and context menu item for the selected files. Each button is hidden when its handler is omitted, folders are never offered for deletion, the listing reloads after either succeeds and a thrown error goes to `onError`.
- Delete, from the toolbar (enabled while any file is selected) or the menu, goes through one confirmation that names the file or gives the count. `onDelete` runs once per file inside one mutation, so the listing reloads once; each failure goes to `onError` without stopping the rest, and the selection clears afterwards.
- The open folder is kept in the `?path=` query param so reloads and back/forward stay in place.

## Constraints

- Path validation (rejecting `..` and absolute paths) belongs to the caller's routes; the component only passes the relative path through.
- Styling is Tailwind classes. A consumer must include this package's source or published files in its Tailwind content paths.
