# DocsExplorer

`libs/@vigilant-broccoli/docs-explorer` — file-tree + search shell for browsing markdown docs. Markdown/checklist rendering and edit mode are layered on top by `DocsViewer`.

The `component-library` sandbox has a Utilities > Docs Explorer page that links to docs.harryliu.dev and renders this file — it doesn't mount the component, which needs a notes tree to browse.

## Exports

- `DocsExplorer` — tree/search shell, content-agnostic
- `DocsNode`, `DocsSearchResult` types
- `DocsViewer`, `FILE_PARAM` — wraps `DocsExplorer` with markdown + checklist view modes and edit mode; `FILE_PARAM` (`'file'`) is the URL query key both consuming apps sync the selected path through

## DocsExplorer Props

- `nodes`, `getContent(path)` — tree + file fetch
- `renderContent(content, navigate, sourcePaths)` — how the selected file(s) render; `sourcePaths` is `[selectedPath]` normally, or every checked path in multi-select mode; `DocsViewer` supplies the markdown/checklist switch here
- `search(query)` — optional; enables the search box
- `urlSync: { get, set }` — syncs selected file to the URL instead of component state alone; `set(path, { replace })` may rewrite the current history entry instead of pushing (`createSearchParamUrlSync` supports it, others keep pushing)
- `enableMultiSelect` — off by default; adds a toggle button in the sidebar header (styled like the graph toggle, filled when on). `docs-md` turns it on through `DocsViewer`
- `viewModes`, `currentViewMode`, `onViewModeChange` — populate the content-pane dropdown, which sits in a sticky bar so it stays reachable while scrolling; as the content's first `h1` scrolls under the bar, the bar fades and slides in that heading's text in proportion to how much of the heading is hidden
- `onEdit` — adds an Edit item to the content-pane dropdown
- `renderGraph(navigate)` — optional; enables the graph toggle (left of the content pane's ellipsis on desktop, the sidebar header on mobile, or `g` outside text fields and dialogs) and renders its result in the content pane (see [note-graph.md](./note-graph.md))
- `getShareUrl(path)` — optional; adds a Share item (before Copy markdown) to the single-note ellipsis menu, hidden when absent, in aggregate mode or when it returns `null`. The host owns the URL: selection is in-memory, so the explorer cannot build one. Share opens `ShareDialog` (`share-dialog.tsx`) with the note name, a read-only link with a Copy link button and a QR code rendered client-side with `qrcode`
- `sidebarTitle`, `searchPlaceholder`, `emptyMessage` — copy overrides

## DocsViewer Props

- `getStructure`, `getContent`, `search` — same contracts as DocsExplorer
- `saveContent(path, content)` — optional; its presence alone enables the Edit action
- `getGraph()` — optional; supplies the note graph and enables the graph toggle (see [note-graph.md](./note-graph.md)). A ghost settings icon holds scope (Global/Local), depth (a 1–10 hops select), a color scheme select, a node glow switch and force sliders (each range symmetric around its default, so they start centered): a popover on desktop (`md:` and up), a dialog on mobile. The hop select only shows in local scope; opening any file switches to local
- `urlSync`, `enableMultiSelect`, `getShareUrl` — forwarded to DocsExplorer

## Behaviour

- When a graph renderer is available, the initial desktop view (768px and wider, matching `md:`) opens the graph unless `urlSync` supplies a selected file. Mobile starts in the file browser. This default is applied after mount for SSR compatibility; resizing and subsequent renders preserve the user’s selection.

- When `search` is provided, `/` (outside text fields and dialogs) focuses the search input and select its text; on mobile it first switches back to the file browser. Bound through react-lib's [`useFocusSearchShortcut`](../../../react-lib/docs/features/focus-search-shortcut.md)
- View mode (`markdown` / `checklist`) persists in `localStorage` (`docs-md:view-mode`) independent of which file is open; defaults to markdown
- Checklist view renders the full document exactly like markdown view — only top-level lists become checkboxes; tables, prose, code, headings pass through unchanged. A table of contents (the list under a "Table of Contents"/"Contents"/"TOC" heading, or one made only of in-page `#` links) also renders as plain markdown, but still takes its list number so later lists keep their saved ids
- Checking an item checks or unchecks everything nested under it; each ancestor is then checked exactly when all its children are, and a partly done parent shows the indeterminate checkbox
- Checkbox state persists per file (`localStorage`, key `docs-checklist:<path>`), keyed by structural position (`list<N>.<itemIndex>`, nested via `.l.`) — not content, so state can go stale if list ordering changes; in aggregate mode (below) the key is a composite of every selected path joined with `|`, so the same set of files always shares one saved state
- All rendered HTML (both view modes) is sanitized with DOMPurify before injection
- Fenced ` ```mermaid ` blocks render as diagrams in both view modes (`mermaid-diagrams.ts`): `mermaid` is lazy-loaded on first use, runs with `securityLevel: 'strict'` after DOMPurify, picks its `dark`/`default` theme from the painted background and re-renders when the theme toggles; a syntax error leaves the original code block in place. `docs-md` and `context-md` both get this through `DocsViewer`
- Relative markdown links are intercepted and routed through `urlSync`/`onNavigate` instead of a real browser navigation — no consuming app has a per-file route, so a plain `<a href>` navigation would 404 or reload the whole app. In-page anchors and cross-file `#heading` targets read and write `window.location.hash`
- External `http(s)` links open in a new tab when the viewer runs inside an iframe (local-manager's `/embed`): loading them in the frame fails for sites that send `X-Frame-Options`/CSP `frame-ancestors`. Unframed, they navigate normally
- Headings get GitHub-style slug `id`s (`markdown-config.ts`'s `createHeadingRenderer`, via `github-slugger`) so `[Section](#section)`-style TOC/cross-file anchors resolve — `marked` v5+ no longer assigns heading ids on its own
- `createHeadingRenderer()` builds a fresh renderer+slugger per parse call rather than a shared/global one — `marked`'s own heading-id extensions track dedup state in module scope, which breaks under React Strict Mode's double-invoked effects/memos (two overlapping parses for the same content stomp on each other's dedup reset) and under any real overlapping parse (e.g. switching files before the previous parse settles)
- `createSearchParamUrlSync(param = FILE_PARAM)` is the shared `urlSync` (docs-md, context-md, grind-75-react, hearth's recipes): `get`/`set`/`clear` on a query param plus `popstate` `subscribe`. Its `set()` must preserve `window.location.hash` — `DocsExplorer` calls `urlSync.set()` on initial mount too, even when just echoing back the file it already read from the URL, so rebuilding from the query params alone drops a direct link's `#section`
- Cross-file links with a section anchor (`./file.md#section`) carry the hash through: `resolveNoteLink` keeps it on the resolved target, and `selectFile` only writes `window.location.hash` when the caller actually supplied one — plain path selections (tree click, search result, initial URL sync) leave the hash alone, since the initial-mount sync always calls `selectFile` with a bare path and would otherwise clobber a hash that was already correctly in the URL from a direct link
- Known gap: selecting a _different_ file via the tree or search doesn't clear a leftover hash from the previous file — harmless (no matching heading means `scrollToUrlHash` no-ops) but the stale fragment stays visible in the URL until something overwrites it
- `scrollToUrlHash()` (`note-links.ts`) runs after content renders in both viewers — the browser's native scroll-to-fragment only fires around initial page load, which is well before this SPA's async-fetched content (and its heading ids) exist in the DOM
- Checking multiple files (checkbox beside each file in the tree and in search results) switches the content pane to an aggregate view: their contents join with `\n\n---\n\n`, with a mode toggle (in the dropdown) for whether to keep every file's headings as-is, drop just each file's leading `#` title, or strip all headings — `saveContent`/edit is disabled in this mode. The mode persists as `docs-md:aggregate-mode` (removed for the default)
- In multi-select mode only the checkbox changes the selection; a row click opens the note and keeps the selection, and the next checkbox change returns to the aggregate view. With two or more checked, clicking a checked file instead scrolls the aggregate view to that file's section (an empty `data-aggregate-section` marker per file, in the displayed content only; Copy markdown stays clean), highlights it in the sidebar and replaces the URL's `?file=` so the back stack is unchanged
- The mode (`docs-md:multi-select`) and checked paths (`docs-md:multi-select-paths`) persist; after reload the paths are restored once the tree loads, dropping any that no longer exist, and the aggregate view reopens, scrolled to the `?file=` section when it is one of them. The restore runs after the initial URL open so it wins over `?file=`
- In the aggregate view the sticky bar's heading and the sidebar highlight follow the section under the bar (the last `data-aggregate-section` marker at or above it) as the user scrolls. When the section has no `h1` (collapsed and flat modes strip them), the bar shows the note's title instead, read from the marker's `data-aggregate-title` (the raw content's first `# ` heading, else the file name without `.md`) and fully visible; scroll-driven highlight updates pause for the length of a jump's smooth scroll so the sections it passes do not flicker through
- While files are checked but a single note or the graph covers the aggregate view, a "Back to selection" link beside Clear returns to it at the section last viewed
- Sidebar rows show the selected color while pressed (`active:`), since the click that selects them fires on release
- Note-link resolution in aggregate mode is imprecise: `MarkdownViewer` resolves relative links against only the first selected file's directory (wrong for links belonging to a later file in a different directory), and `ChecklistViewer` gets the composite `aggregate:path1|path2` string as its "path", which isn't a real path at all — relative link clicks there resolve incorrectly
- Edit mode swaps content for a plain `<textarea>` (no live preview); content-pane dropdown also has "Copy markdown" and "Back to files" (mobile only). The graph view shares the note view's top bar and menu, except at the root (no note open), where the bar's buttons float over the graph without the bar and the graph cannot be toggled off (no toggle button; `g` and the mobile sidebar button only open it); note actions (view modes, edit, `extraActions`, copy) need an open note, and all but copy close the graph before running
- File navigation (tree, search, note links, graph) pushes the previously open file onto an in-memory stack; the content bar's back arrow pops it, so A → B → C goes back C → B → A. The root view (no file open, including a direct `?file=` load) is the bottom entry: going back to it resets the content pane like a fresh visit and calls `urlSync.clear()` (both apps drop `?file=`). Going back does not push, and the stack resets on reload. Browser back/forward reopen the file the URL names through `urlSync.subscribe` (both apps listen to `popstate`) without writing the URL again; landing on the stack's top entry pops it, anything else pushes like a normal navigation. The in-page arrow stays in-app rather than calling `history.back()`, so it never leaves the site or moves an embedding host's history
- Search is debounced 300ms; Arrow keys move focus between the search box and result list, Escape or the box's trailing × (react-lib's `ClearableInput`) clears the query
- Mobile collapses to two full-width panels (sidebar/content) toggled by a back button — no side-by-side layout below `md:`. On desktop the panel icon left of the sidebar title hides the sidebar so content takes the full width; a matching icon at the content pane's top left restores it, at the same spot (the sidebar header shares the content bar's `px-2 pt-1` inset, and the root and graph overlays add back the card padding absolute children skip), and `f` (outside text fields and dialogs) toggles it. The sidebar and graph buttons' hover titles name their key, e.g. "Hide sidebar (f)"; the accessible name stays the plain label. The width animates over 200ms. The collapsed state is in-memory and ignored on mobile
- Search isn't implemented in these libs — each consuming app supplies its own `search` function. `docs-md` and `context-md` both use `createDocsSnapshotSource`, which fetches every note body once (in-memory per-session cache, in-flight fetch dedup so overlapping searches don't double-fetch) and combines a plain substring content match with a local subsequence filename scorer
- The filename scorer (`docs-snapshot-source.ts`) keeps fuse.js' score convention — 0 is perfect, lower is better — so callers that sort ascending are unaffected. It runs three tiers, each in its own score band so a weaker match can never outrank a stronger one: contiguous substring `[0, 0.2)`, gapped subsequence `[0.2, 0.4)`, then bounded Damerau-Levenshtein `[0.4, 0.6)`. Each tier rejects on its own terms rather than against a shared cutoff, and the two gapped tiers both break ties on coverage — without it `github.md` and `github-actions.md` score identically and the winner is decided by array order
- The fuzzy tier exists because a subsequence scan survives a dropped character for free but nothing else: `githb` matches `github.md`, while `gtihub` (transposition), `gothub` (substitution) and `githhub` (insertion) all fail it. It is gated on a 5-character minimum, one permitted edit per 4 query characters, and the query's first character opening a word in the target (start of name, or after `-_/.`)
- That first-character gate is doing real work: without it `todo` sits one transposition from `tdoo` inside `outdoor.md`, which is precisely the noise fuse.js produced. Typists rarely fumble the first character, so the gate costs almost no recall
- Beating fuse.js on both recall and precision at once is not a better-tuned tradeoff — it is a different cost model. Bitap (`fuse.mjs:450-452`) only carries substitution, insertion and deletion terms from one error level back, so it cannot express a transposition and charges 2 edits for one: measured against `github`, `gothub`/`githb`/`githuub` score `1/6` but `gtihub` scores `2/6`. It matched `gtihub` only because `threshold: 0.4` on a 6-character pattern permits 2 errors — and that same headroom is what let `todo` reach `outdoor.md` and `k8s` reach `shakshuka.md`. Charging 1 for a transposition buys the same typo recall inside a budget less than half as wide
- Measured over the 507-file snapshot, the source file ranks #1 for 54/54 single-typo queries in each of the four classes; fuse.js managed 47/54
